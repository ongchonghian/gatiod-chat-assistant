# 02 — Clinical Display Registry: spine labels + extractor comparison fix

Status: done
Category: enhancement

## What to build

Register all spine clinical translations into the registry and wire the extractor comparison message to use them. This is the highest-priority consumer slice because the extractor comparison message (ADR-0004) is the currently-broken path that surfaced this work.

**Registry additions:**
- Migrate `SPINE_REGION_LABELS`, `SPINE_BLADDER_BOWEL_LABELS`, `SYSTEM_LABELS` (spine entry) from `confirmationBuilder` into the registry.
- Register a spine value formatter for `SpineCategoryEntryFact` arrays that delegates to the existing `buildSpineEntry` logic, producing the same terse table format already used in confirmation cards (category → severity → modifiers).
- Register scalar label registrations for `spine_region` → `"Region"` and `spine_entries` → `"Diagnosis entries"`.
- Register clinical translations for all spine boolean/enum modifiers: `monoparesisHalving`, `bladderBowelSeverity`, `discCordInvolvement`, `spondylolysisPathway`.

**Extractor comparison fix:**
- Update `formatExtractionSummary` in `extractorComparison.ts` to call `factKeyLabel` for the bullet label and `factValueDisplay` for the value, replacing the current raw-key + `formatValue` pattern.
- Update `buildComparisonOffer` to translate the conflict-line field names via `factKeyLabel` before joining them into the `"These fields differ: …"` string.

- [x] Unit tests assert label and display output for all registered spine fact keys
- [x] Unit tests assert end-to-end comparison message string for a representative spine extraction pair (one with conflicts, one without)
- [x] `SPINE_REGION_LABELS` and `SPINE_BLADDER_BOWEL_LABELS` definitions removed from `confirmationBuilder`; `confirmationBuilder` imports them from the registry

## Agent Brief

**Category:** enhancement
**Summary:** Register spine clinical translations in the `clinicalLabels` module and update the extractor comparison formatter to use them, eliminating raw JSON and schema identifiers from spine disambiguation messages.

**Current behavior:**
When the regex extractor and LLM slot extractor produce different spine results and the system presents both interpretations for the doctor to choose between, the comparison message bullet-renders each fact as `• **factKey**: rawValue`. For `spine_entries`, `factKey` is the literal string `spine_entries` and `rawValue` is the JSON-serialised `SpineCategoryEntryFact` array (e.g. `[{"diagnosisCategory":"intervertebral_disc","severityKey":"disc31_persistent_motor_or_motor_sensory","monoparesisHalving":false,...}]`). For `spine_region`, the value is the raw enum string `lumbo_sacral`. The "These fields differ" conflict line also names raw fact keys.

The extractor comparison's `formatExtractionSummary` function contains its own `formatValue` helper that handles ROM joints and simple objects but falls through to `JSON.stringify` for spine entries arrays.

**Desired behavior:**
After this change, a spine comparison message reads in clinical language throughout:

- Bullet labels use registered labels: `spine_region` → `"Region"`, `spine_entries` → `"Diagnosis entries"`
- `spine_region` values render as titled region names: `lumbo_sacral` → `"Lumbo-Sacral"`, `cervical` → `"Cervical"`, `thoraco_lumbar` → `"Thoraco-Lumbar"`
- `spine_entries` values render in the same terse format used in confirmation cards: `"Intervertebral disc — Persistent motor or motor-sensory deficit"` with modifiers appended as needed (e.g. `", monoparesis halving"`, `", bladder/bowel: Incomplete (both)"`)
- The `"These fields differ:"` conflict line uses clinical labels: `"These fields differ: Severity, Region"` not `"These fields differ: severityKey, spine_region"`
- The `buildSpineEntry` clinical formatting logic (already correct in `confirmationBuilder`) is reused via the registry — not duplicated

Existing spine label constants (`SPINE_REGION_LABELS`, `SPINE_BLADDER_BOWEL_LABELS`) move from `confirmationBuilder` into the registry. `confirmationBuilder` imports them back from the registry so its output is unchanged.

**Key interfaces:**
- `factKeyLabel(system, factKey)` — the registry function wired for spine fact keys: `spine_region`, `spine_entries`, `monoparesisHalving`, `bladderBowelSeverity`, `discCordInvolvement`, `spondylolysisPathway`
- `factValueDisplay(system, factKey, value)` — the registry function with spine value formatters registered; `spine_entries` formatter delegates to the same logic as `buildSpineEntry` in `confirmationBuilder`
- `formatExtractionSummary(facts, displayValues, pendingObs)` — replace its inline `formatValue` + raw-key bullet pattern with calls to `factKeyLabel` / `factValueDisplay`
- `buildComparisonOffer(system, sourceText, primary, shadow)` — update `conflictKeys.join(", ")` to map each key through `factKeyLabel` first
- `SpineCategoryEntryFact` — the value type that the spine value formatter must handle (array of entries with `diagnosisCategory`, `severityKey`, and modifier fields)
- `getSeveritiesForCategory(category, opts)` — the severity label lookup already used in `confirmationBuilder`; the registry formatter calls this same function

**Acceptance criteria:**
- [x] A spine extractor comparison message rendered from a fully-populated `SpineCategoryEntryFact` array contains no JSON brackets, no camelCase field names, and no severity key codes
- [x] `spine_region: lumbo_sacral` renders as `• **Region**: Lumbo-Sacral` in the comparison message
- [x] `spine_entries` with a disc entry renders as `• **Diagnosis entries**: Intervertebral disc — Persistent motor or motor-sensory deficit` (exact label from `getSeveritiesForCategory`)
- [x] Boolean modifier `monoparesisHalving: true` appends `", monoparesis halving"` to the entry summary
- [x] `bladderBowelSeverity` enum values render via the existing `SPINE_BLADDER_BOWEL_LABELS` strings
- [x] Conflict line for a `spine_region` difference reads `"These fields differ: Region"` not `"These fields differ: spine_region"`
- [x] `SPINE_REGION_LABELS` and `SPINE_BLADDER_BOWEL_LABELS` have exactly one definition site (the registry); `confirmationBuilder` imports from the registry
- [x] Unit tests cover all registered spine fact key labels and representative value formats
- [x] Unit tests cover end-to-end `buildComparisonOffer` output for a spine pair with a region conflict and for a spine pair with no conflicts
- [x] All existing `confirmationBuilder` and `extractorComparison` tests pass without modification to their assertions

**Out of scope:**
