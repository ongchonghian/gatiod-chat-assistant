## What to build

Create the `clinicalLabels` module that will become the single translation layer between V2 internal fact keys/values and doctor-facing strings. This slice establishes the public interface and wires nothing yet — it is the foundation all subsequent slices build on.

The module exposes exactly two pure functions:

- `factKeyLabel(system, factKey) → string` — returns a human-readable field label for a given system's fact key (e.g. `spine_region` → `"Region"`). Falls back to a sanitised version of the raw key when no registration exists.
- `factValueDisplay(system, factKey, value) → string` — returns a formatted clinical string for a fact value. Falls back to `String(value)` when no registration exists.

Internally the module supports per-system registration of a label map and a value formatter map. No registrations are added in this slice; the module is empty but fully functional (all calls hit the safe fallback).

## Agent Brief

**Category:** enhancement
**Summary:** Create the `clinicalLabels` module — a pure two-function interface that translates V2 fact keys and values to doctor-facing strings, with safe fallbacks for unregistered inputs.

**Current behavior:**
No clinical display module exists. Every rendering path (confirmation builder, extractor comparison, result renderers) defines its own label strings inline or falls back to `JSON.stringify` for complex values. There is no contract that prevents raw schema identifiers from leaking into doctor-facing output.

**Desired behavior:**
A `clinicalLabels` module exists and is importable. It exports exactly two pure functions:

- `factKeyLabel(system: GatiodSystemKey, factKey: string): string` — returns the human-readable label registered for that system's fact key. When no registration exists, returns a sanitised fallback (e.g. spaces substituted for underscores, title-cased) — never the raw key verbatim, never an empty string.
- `factValueDisplay(system: GatiodSystemKey, factKey: string, value: unknown): string` — returns a formatted clinical string for the value. When no registration exists, returns `String(value)` for primitives and a safe non-JSON representation for objects/arrays — never `JSON.stringify` output, never `"[object Object]"`.

In this slice no registrations are added. Every call hits the fallback path. Consumers are added in subsequent issues.

**Key interfaces:**
- `factKeyLabel(system: GatiodSystemKey, factKey: string): string` — exported pure function
- `factValueDisplay(system: GatiodSystemKey, factKey: string, value: unknown): string` — exported pure function
- Internal registration API (not exported) — accepts a `GatiodSystemKey`, a label map `Record<string, string>`, and an optional value formatter map `Record<string, (value: unknown) => string>`

**Acceptance criteria:**
- [x] `factKeyLabel` and `factValueDisplay` are importable from the new module
- [x] `factKeyLabel` called with any valid or invalid `GatiodSystemKey` and any string returns a non-empty string without throwing
- [x] `factKeyLabel` fallback never returns the raw key verbatim when the key contains underscores (e.g. `spine_region` must not pass through unchanged)
- [x] `factValueDisplay` called with an object value returns a non-JSON, non-`[object Object]` string without throwing
- [x] `factValueDisplay` called with `null` or `undefined` returns a safe placeholder string (e.g. `"—"`)
- [x] Unit tests cover: unknown system + unknown key, known system + unknown key, object value, array value, null value, primitive value
- [x] No existing test suites fail — no consumer is wired to the module yet

**Out of scope:**
- Any label or value formatter registrations (those are issues 02 and 03)
- Any changes to `confirmationBuilder`, `extractorComparison`, or result renderers
- Exported types beyond the two public functions
