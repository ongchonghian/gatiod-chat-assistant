# 03 — Clinical Display Registry: all remaining systems + Visual/CNS placeholders

Status: done
Category: enhancement

## Parent

## What to build

Extend the registry with label and value formatter registrations for every other V2 system so that extractor comparison messages for any system are fully clinical. Includes placeholder registrations for CNS and Visual (which are not yet `structured_live`) so that their promotion in Sprint 6 does not require a registry backfill.

**Upper limb:**
- Fact key labels: side, bilateral mode, ROM joints, nerve selections, amputation (level + finger), shortening.
- Value formatters: ROM joints map (migrate the existing `formatValue` ROM branch from `extractorComparison.ts`); nerve selections array (named nerve groups); amputation level enum; finger amputations map.

**Lower limb:**
- Fact key labels: side, bilateral mode, ROM joints, nerve selections, leg amputation, toe amputations, shortening, DBE selections.
- Value formatters: ROM joints map (same formatter as upper limb); nerve selections array; leg amputation level enum; toe amputations map; DBE selections array.

**Hearing:**
- Fact key labels: path, affected ear, left/right AHL, age.
- Value formatters: AHL values with unit suffix (`"42 dB"`); laterality enum (`left → "Left"`, etc.); path enum (`nid → "NID"`, `injury → "Injury"`).

**Respiratory:**
- Fact key labels: FVC, FEV1, DLCO, VO2 Max, test results map.
- Value formatters: test class labels; measurement values with units.

**Renal:**
- Fact key labels and scalar value formatters for all renal fact keys.

**Gastro / Digestive:**
- Fact key labels and scalar value formatters for all gastro fact keys.

**CNS (placeholder):**
- Stub registrations that return the fact key sanitised and values as `String(value)`. Marked with a `// TODO: Sprint 6 — full CNS label registrations` comment. Ensures no crash or raw-JSON leak if CNS comparison messages are encountered before Sprint 6.

**Visual (placeholder):**
- Same placeholder treatment as CNS, with diplopia zone keys pre-registered with their correct clinical labels (`central_30 → "Central 30°"`, `30_to_60 → "30°–60°"`, `beyond_60 → "Beyond 60°"`, `uncorrectable → "Uncorrectable"`) since the zone vocabulary is already finalised in the policy (REQ-A4).

## Agent Brief

**Category:** enhancement
**Summary:** Register clinical labels and value formatters for all remaining V2 systems (upper limb, lower limb, hearing, respiratory, renal, gastro) and add placeholder registrations for CNS and Visual, so that extractor comparison messages for any system are free of raw identifiers.

**Current behavior:**
The `clinicalLabels` registry (created in issue 01, extended for spine in issue 02) has no registrations for upper limb, lower limb, hearing, respiratory, renal, gastro, CNS, or Visual. Extractor comparison messages for these systems fall through to the registry's safe fallback — which returns sanitised key names and `String(value)` for values, but does not produce full clinical formatting (e.g. ROM joints still render as a raw object summary rather than `"hip: flexion 90°, extension 10°"`).

Additionally, the extractor comparison module contains a `formatValue` helper with a bespoke ROM joints branch. That branch correctly handles `isAnkylosed` and `measurements` structures but is isolated inside the comparison module rather than shared via the registry.

**Desired behavior:**
After this change, every `structured_live` system has full label and value formatter coverage in the registry, and the two systems not yet live (CNS, Visual) have placeholder coverage that prevents any future crash or raw-JSON leak.

**Per-system requirements:**

*Upper and lower limb (share ROM formatter):*
- `side` → `"Side"`, value: `left → "Left"`, `right → "Right"`
- `bilateral_mode` → `"Bilateral mode"`, value: `same → "Same findings for both"`, `separate → "Separate findings per limb"`
- `rom_joints` → `"ROM measurements"`, value: migrate the `formatValue` ROM joints branch from the extractor comparison module into the registry (joint names, direction-angle pairs, ankylosed flag). This is the one existing implementation that must not regress — port it exactly, then delete the duplicate from the comparison module.
- `nerve_selections` → `"Nerve deficits"`, value: array of named nerve groups joined with commas
- `leg_amputation` / finger/toe amputation keys → `"Amputation level"` etc., values: clinical level names (`"Above knee"`, `"Below knee"`, etc.)
- `shortening_cm` → `"Shortening"`, value: append `" cm"` unit
- `dbe_selections` → `"DBE injuries"`, value: array of DBE condition names joined with commas

*Hearing:*
- `path` → `"Assessment path"`, value: `nid → "NID"`, `injury → "Injury"`
- `affected_ear` / laterality keys → `"Affected ear"`, value: `left → "Left"`, `right → "Right"`, `both → "Both"`
- AHL fact keys → `"Left ear AHL"` / `"Right ear AHL"`, value: append `" dB"` unit
- `age` → `"Age"`, value: append `" years"`

*Respiratory:*
- Test result fact keys → clinical test names (`"FVC"`, `"FEV₁"`, `"DLCO"`, `"VO₂ Max"`)
- Class label values: render using the existing test classification label strings already present in the respiratory renderer

*Renal and Gastro:*
- All fact keys → title-cased labels derived from the slot schema
- Scalar enum values → render using display strings present in the respective renderers or slot schemas

*CNS (placeholder):*
- Register all CNS fact keys with sanitised labels and `String(value)` formatters
- Each registration includes a comment: `// TODO: Sprint 6 — replace with full CNS clinical labels`
- Must not crash; must not produce raw JSON

*Visual (placeholder):*
- Same placeholder treatment as CNS, except diplopia zone keys are registered with their correct final clinical labels now (vocabulary is already policy-finalised): `central_30 → "Central 30°"`, `30_to_60 → "30°–60°"`, `beyond_60 → "Beyond 60°"`, `uncorrectable → "Uncorrectable"`, `none → "No diplopia"`

**Key interfaces:**
- Per-system registration in the `clinicalLabels` module — label maps and value formatter maps for `upper_limb`, `lower_limb`, `hearing`, `respiratory`, `renal`, `gastro_digestive`, `cns`, `visual`
- The ROM joints `formatValue` branch currently inside the extractor comparison module — this logic moves to the registry's limb ROM formatter; the comparison module deletes its local copy
- Slot schema types for each system (the `SlotDefinition` structures) — read these to discover all fact keys and their value types
- Existing renderer label strings — consult each system's result renderer for clinical names already in use (these are the canonical strings to reuse)
- `SYSTEM_LABELS` in `confirmationBuilder` — after this issue, all entries should resolve to registry lookups; no duplicate definitions

**Acceptance criteria:**
- [x] Extractor comparison messages for upper limb, lower limb, hearing, respiratory, renal, and gastro contain no raw JSON, no camelCase field names, and no raw enum values
- [x] ROM joints map renders as `"hip: flexion 90°, extension 10°"` (not a JSON fragment) — this is functionally identical to the existing `formatValue` ROM branch
- [x] The `formatValue` function (or its ROM joints branch) is removed from the extractor comparison module; the registry is the sole ROM formatter
- [x] Hearing AHL values render as `"42 dB"` (with unit); laterality renders as `"Left"` / `"Right"` / `"Both"`
- [x] `bilateral_mode: same` renders as `"Same findings for both"` (not `same`)
- [x] CNS comparison messages do not crash and do not contain raw JSON
- [x] Visual diplopia zone values render as their clinical labels (`"Central 30°"` etc.)
- [x] `SYSTEM_LABELS` in `confirmationBuilder` has no definitions that duplicate registry entries
- [x] Unit tests cover representative fact key labels and value formats for each of the six newly-registered systems
- [x] All existing tests for `extractorComparison`, `confirmationBuilder`, and all result renderers pass without modification to their assertions

**Out of scope:**
