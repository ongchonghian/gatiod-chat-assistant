# 05 — Confirmation builder: migrate generic fallback to registry

Status: done
Category: enhancement

## Parent

[Clinical Display Layer PRD](../PRD.md)

## What to build

Update the generic `default:` fallback branch in `confirmationBuilder` — the path reached by systems that do not yet have a bespoke body builder — to call the clinical display registry instead of emitting raw fact keys and `JSON.stringify` values.

The fallback currently iterates `Object.entries(facts)` and produces lines like `key: JSON.stringify(value)` or `ek: ev` for object entries. Replace this with `factKeyLabel(system, key)` for labels and `factValueDisplay(system, key, value)` for values.

Also update the missing-fields error messages that currently expose internal fact key names (e.g. `"spine_region"`, `"spine_entries"`) to use clinical labels from the registry.

Add snapshot regression tests for the generic fallback path using a representative system that currently reaches this branch.

## Acceptance criteria

- [x] Snapshot tests for the generic fallback path confirm no raw keys or JSON in the output
- [x] Bespoke body builders (spine, hearing) are unchanged
- [x] All existing `confirmationBuilder` tests pass

**Category:** enhancement
**Summary:** Replace the raw-key + `JSON.stringify` pattern in `confirmationBuilder`'s generic fallback branch with `factKeyLabel` / `factValueDisplay` calls, and translate missing-field error messages to use clinical labels.

**Current behavior:**
`confirmationBuilder` has bespoke body builders for spine and hearing that already produce clinical output. All other systems fall through to a generic `default:` branch that iterates the confirmed facts and produces lines using the raw fact key as the label and either a flat object entry map (`ek: ev`) or `JSON.stringify(v)` for the value. This branch also emits missing-field error reasons that contain raw fact key names (e.g. `"spine_region is required"`).

**Desired behavior:**
The generic fallback branch calls `factKeyLabel(system, key)` and `factValueDisplay(system, key, value)` for every fact in the confirmed set. The visual output format (bullet list, one line per fact) is unchanged; only the label and value content changes. Missing-field error reasons use clinical labels: `"Region is required"` not `"spine_region is required"`.

The bespoke spine and hearing body builders are not touched — they already produce correct output and source their labels from the registry (after issue 02).

**Key interfaces:**
- `factKeyLabel(system, factKey)` and `factValueDisplay(system, factKey, value)` — called in the `default:` branch of the `buildStructuredBody` switch
- `ConfirmationBuildResult` — unchanged; only the markdown string content of the `message` field changes for the fallback path
- Missing-field error messages (`reason` string in `{ ok: false, reason, missingFields }`) — clinical labels replace raw fact keys in the reason text
