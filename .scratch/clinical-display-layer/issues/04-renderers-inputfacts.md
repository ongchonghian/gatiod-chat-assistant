# 04 — Result renderers: migrate inputFacts to registry

Status: done
Category: enhancement

## Parent

[Clinical Display Layer PRD](../PRD.md)

## What to build

Update every result renderer's `fullBreakdown.inputFacts` list construction to use the clinical display registry instead of the current `${key}: ${JSON.stringify(fact.value)}` pattern. This affects the expanded calculation breakdown that is shown inline when auto-expansion triggers (DBE/ROM conflicts, multi-stream results, etc.) and is always available via the "View full calculation breakdown" chip.

Each renderer iterates its relevant fact keys, calls `factKeyLabel(system, key)` for the label and `factValueDisplay(system, key, fact.value)` for the value, and joins them as before. No change to the `fullBreakdown` type contract, the auto-expand logic, or any other part of the renderer output.

Update existing renderer snapshot tests to reflect the new clinical strings. Snapshot diffs are the acceptance signal — no additional test scenarios are needed beyond what already exists.

## Agent Brief

**Category:** enhancement
**Summary:** Replace `JSON.stringify(fact.value)` in every result renderer's `inputFacts` construction with `factKeyLabel` / `factValueDisplay` calls, so the expanded calculation breakdown shows clinical labels and values.

**Current behavior:**
Every result renderer builds a `fullBreakdown.inputFacts` string array by iterating a fixed list of fact keys and producing entries in the form `${key}: ${JSON.stringify(fact.value)}`. For structured values this produces raw JSON (e.g. ROM joint objects, spine entry arrays). For scalar values it produces undecorated strings without units or title-casing.

This list is surfaced to the doctor in the expanded breakdown section — triggered inline when auto-expand conditions fire and accessible via the "View full calculation breakdown" chip.

**Desired behavior:**
Each `inputFacts` entry uses `factKeyLabel(system, factKey)` as the label and `factValueDisplay(system, factKey, fact.value)` as the value. The visual format of the list entry itself (`"Label: Value"`) is unchanged; only the content of label and value changes.

Representative before/after for each system:
- Spine: `"spine_entries: [{...}]"` → `"Diagnosis entries: Intervertebral disc — Persistent motor or motor-sensory deficit"`
- Lower limb: `"rom_joints: {\"hip\":{...}}"` → `"ROM measurements: hip: flexion 90°, extension 10°"`
- Hearing: `"left_ahl: 42"` → `"Left ear AHL: 42 dB"`
- Respiratory: `"fvc: 0.78"` → `"FVC: 0.78"` (with class label if registered)

No other part of any renderer changes: not the summary line, not the `resultSummary` object, not the auto-expand conditions, not `fullBreakdown`'s type shape.

**Key interfaces:**
- `factKeyLabel(system, factKey)` and `factValueDisplay(system, factKey, value)` — called once per fact key in each renderer's `inputFacts` block
- `fullBreakdown.inputFacts: string[]` — the type shape is unchanged; only string content changes
- `AssessmentRenderResult` — unchanged; this issue touches only the `fullBreakdown.inputFacts` array within it

**Acceptance criteria:**
- [x] No renderer constructs any `inputFacts` entry using `JSON.stringify` on `fact.value`
- [x] Spine renderer expanded breakdown contains `"Diagnosis entries: …"` with a clinical entry summary, not raw JSON
- [x] Lower-limb renderer expanded breakdown contains ROM joints in `"hip: flexion 90°"` format, not a JSON object
- [x] Hearing renderer expanded breakdown contains `"Left ear AHL: 42 dB"` (unit suffix present), not `"left_ahl: 42"`
- [x] All existing renderer snapshot tests are updated to assert the new clinical strings and pass
- [x] `fullBreakdown` type shape, auto-expand logic, result summary strings, and `suggestedChips` are all unchanged

**Out of scope:**
- Changes to result summary lines (the `"System-generated GATIOD PI%: X%"` line and stream lines)
- Changes to the `fullBreakdown` structure other than `inputFacts`
- `confirmationBuilder` changes (issue 05)
- Any renderer output when `displayMode` is `"summary"` (only the `fullBreakdown.inputFacts` list is affected)
